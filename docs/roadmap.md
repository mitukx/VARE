Continue only with a focused precision fix and production-method regression; do not duplicate the existing PR. ## E0 — Harness integrity

The executable environment evaluator now rechecks protected hashes after each test and metric command, stops after persistent mutation, discards a metric produced during mutation, and awards zero score when integrity fails. A frozen CPU fixture reproduced the pre-fix false pass (`passed=true` after a test rewrote a protected evaluator file); the post-fix test and metric mutation cases both fail closed while an untampered control passes. GitHub CI passed 169 tests (12 skipped) at the tested source revision. See the [report](protected-evaluator-post-command-report.md) and [retained baseline/fixed records](../results/protected-evaluator-post-command-v1/). This detects persistent changes between commands, not a hostile process that changes and restores files within one command; the runner is not a security sandbox.

All three current task graders reject isolated mutations of the task descriptor, task brief, and evaluator against the unchanged protocol lock. The latest calibration has three untampered controls and nine tamper cases; all controls reach candidate-file validation and all nine mutations are rejected. See [`protocol-integrity/cpu-calibration-v5`](../results/protocol-integrity/cpu-calibration-v5/summary.json).

The trust anchor is the version-controlled protocol lock. This calibration does not authenticate a coordinated edit to the lock and does not sandbox hostile candidate code; those limits are explicit in the [evidence notes](evidence.md).

A separate [promotion-gate regression](promotion-gate-report.md) found that seven non-finite report inputs were accepted before a fail-closed validation change. The frozen CPU grader rejects those inputs and preserves a finite positive control. This is one implementation contract, not an estimate of gate error rates.

The [promotion evidence identity v1](promotion-evidence-identity-report.md) found that omitted evaluation slices and reports labeled for the wrong policy could still lead to candidate acceptance. The gate now requires identical slice coverage, and the engine binds report IDs to the requested policies. A frozen CPU reproduction rejects both cases and preserves a correct control; CI passed 187 tests with 12 skipped. This is E0 bookkeeping integrity, not proof of independent or truthful evaluation.

The [verifier reward contract v1](verifier-reward-contract-report.md) similarly reproduced malformed structured verifier outputs (`score=2.0`, `NaN`, and invalid confidence) reaching the training hook. The validator now checks and snapshots individual and aggregate outputs, engine ingestion before replay, and RVL conversion before optimizer input. The unchanged CPU reproducer rejects malformed outputs and preserves its valid control; CI passed 185 tests with 12 skipped. This is E0 correctness evidence, not reward validity or learning evidence.

A separate [replay group regression](replay-group-freshness-report.md) found that freshness filtering returned a partial group when one member was stale. The fix drops that group while preserving independent fresh groups and per-item mode. This is one replay invariant test, not a learning or performance result.

The RVL GRPO adapter now restores its saved incumbent after partial candidate-training failures that mutate model and optimizer state. The fake-trainer regression checks exception propagation and the next incumbent rollout. Two CPU smokes with one pinned real trainer revision tested distinct locations: after a completed update at the candidate boundary, and inside the real `train_step` after the real optimizer mutation but before return. Both reconstructed model/optimizer/RNG state and checked the next rollout. These remain narrow adapter-level correctness evidence; optimizer-kernel faults and uncatchable process loss are untested. See the [candidate-boundary report](rvl-grpo-partial-failure-report.md), [in-step fault report](rvl-grpo-midstep-fault-report.md), and respective run bundles.

These outcomes calibrate the tasks and graders; they do not show that an agent can discover the fix or that a model improves.

## E2 — Controlled post-training mechanism

The v1 diagnostic and its failed KL rule remain in [`synthetic-dpo-report.md`](synthetic-dpo-report.md). The separate v2 confirmation is reported in [`synthetic-dpo-v2-report.md`](synthetic-dpo-v2-report.md): a training-only development phase selected the update count; the frozen 10-seed confirmation passed its held-out NLL/KL rule, and the audit reconstructs all seed-by-arm metrics. This reaches a narrow synthetic mechanism result. It is not LLM training or capability evidence.

A separate exact finite construction in [`grpo-expected-update-audit-identifiability-v1-report.md`](grpo-expected-update-audit-identifiability-v1-report.md) holds action-conditioned item-label marginals fixed while changing the expected local clipped-GRPO derivative. Its source was selected via exploratory LP search, then verified by rational/surd enumeration and a second same-host implementation. Classify it as a synthetic identifiability witness, not a trained-policy study, an E4 capability result, or a preregistered confirmation.

The follow-up [`grpo-audit-order-characterization-v1-report.md`](grpo-audit-order-characterization-v1-report.md) gives a finite Boolean-function criterion: the highest nonzero Walsh degree of the conditional update is the minimum order of joint reward marginals needed for universal identification. On the stated four-member binary-reward local update, exact enumeration finds degree three for every nonconstant action vector; two-way marginals can fail, and all three-way marginals suffice. This remains synthetic structural theory with unresolved novelty and no finite-sample cost or capability result.

The frozen [`partial clean-label audit study`](grpo-partial-audit-estimator-v1-report.md) then compares 1–4 labels per group across 390 exact reward laws at a matched 12-label budget. The degree-three estimator is unbiased but has higher fixed-budget MSE than full-group auditing in every nondegenerate case in this grid. The lower-order estimators can look slightly better on MSE while failing to identify a constructed update-direction change. This is a narrow synthetic cost diagnostic with oracle Walsh coefficients, not a practical audit policy or capability result; see the [protocol](../protocols/grpo_partial_audit_estimator_v1.json) and [raw bundle](../results/grpo-partial-audit-estimator-v1/run-1/).

The v2 noise arm remains diagnostic and its shuffled-ID arm is invalid. A separate [`v1 noise/shift study`](synthetic-preference-robustness-v1-report.md) was committed before its run. A second implementation now re-trains from retained designs/labels and verifies the v1 arm metrics and gate without sharing runner/auditor code; however, it does not regenerate the Gaussian contexts/action-pair designs or establish cross-version equivalence. The frozen L2 RVL/Qwen campaign remains unrun: its original workload exceeds the current no-spend CPU budget. Do not edit its lock. The initial cached-model [`cpu_lm_dpo_head_v1`](../protocols/cpu_lm_dpo_head_v1.lock.json) result remains a preregistered non-pass. ## E5 — Systems impact

The original evaluation runner now has a narrow local scheduling measurement: five paired one-worker/four-worker campaigns, 80 historical-task grades with consistent outcomes, and a median paired speedup of 3.4857×. Sixteen synthetic reliability cases match their declared classifications. See the [report](scheduler-report.md), [implementation contract](execution.md) and [raw evidence](../results/cpu-scheduler-v1/summary.json).

The durable coordinator also has a frozen same-host CPU measurement of input freshness work. For serial workloads of 8/16/32 unchanged fixture jobs, targeted commit checks were 8/16/32 versus 64/256/1,024 for the previous full refresh. Full export refresh and offline bundle replay remain intact. The measured completion time at 32 jobs was 1.082s versus 28.479s on this machine; treat timing as descriptive. A v1 pilot with a commit-identity mismatch is retained and marked invalid; the cited result is the source-hash-audited v2 experiment. See the [freshness scaling report](freshness-scaling-report.md).

This completes a local systems measurement, not distributed execution or inference performance. **Update 2026-10-09:** source review found that nonmultiple budgets and per-item replay eviction could create undersized groups for group-relative training; the engine now batches complete groups into atomic replay admission, replay evicts whole groups, and grouped sampling fails closed on incomplete legacy groups. A loop-local run serial prevents group ID collisions when callers reuse a round index. Review also found that an RVL evaluation exception or partial candidate restore failure could leave the shared trainer inconsistent with the incumbent identity; the adapter now forces incumbent restoration after either failure. The full CPU suite passes (159 passed, 12 skipped); see the [group-integrity report](rollout-group-integrity-v1-report.md) and [evaluation-recovery report](rvl-grpo-evaluation-recovery-report.md). The one-command clean-checkout runner and independent audit for the synthetic preference robustness study are available in [`scripts/reproduce_synthetic_preference_robustness.py`](../scripts/reproduce_synthetic_preference_robustness.py). It supports fresh, version-specific reruns; an outside human review remains outstanding. An upstream contribution would be a separate result and has not been made here.
