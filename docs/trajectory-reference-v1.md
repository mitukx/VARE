# Trajectory reference contract v1

## Purpose and boundary

This CPU-only reference validates the meaning of recorded agent events before any future post-training adapter consumes them. It is deliberately separate from `Attempt`, `Experience`, RVL rollout, and the trainer. It does not implement a new RL objective, choose harness-specific roles, or claim model-learning results.

The source-level issue motivating the first regression was in `RVLTokenReplayReader.ready_experiences()`: a ready record without a `reward` field was converted to `0.0`. A missing assessment therefore looked like a valid failed task. Both `snapshot()` and `ready_experiences()` now reject empty groups and require an explicit finite numeric reward in `[0, 1]`; snapshot means include ready records only. Explicit `0.0` remains a valid score. The event reference keeps the same distinction for `valid`, `pending`, and `invalid` assessments.

The read-only RVL reader now also retains the original nested generation payload, exact GRPO group ID and size, stored behavior hash and validation status, ready status, and (when present) RVL's singleton verifier-configuration hash. A strict bridge in `vare.integrations.rvl_trajectory` turns one complete group into one model-call and one final-evaluation event per sample. It checks the pinned RVL behavior-hash encodings, detects generation mutation after reading, cross-checks duplicate group IDs, requires the current verifier version, and checks prompt identity, common policy/model/temperature and evaluator labels, exact prompt/output token IDs, token-level behavior log-probabilities, aggregate-logprob consistency, positive sampling temperature, and the declared behavior-distribution label. Legacy replay databases without compatible hashes or the configuration table remain readable by the general reader, but cannot pass through this strict bridge. This bridge is deliberately limited to one prompt/completion per sample; it does not recover branches, tool calls, compaction, or multi-turn context.

## Event format

The checked-in synthetic trace is [`tests/fixtures/trajectory_reference/v1.jsonl`](../tests/fixtures/trajectory_reference/v1.jsonl). Each JSONL row is one event with `schema_version: 1`, `group_id`, declared `group_size`, `execution_id`, unique-per-execution `event_id`, `event_type`, and `branch_id`. Events also carry two independent links:

- `causal_parent_id` records which prior action caused the event.
- `context_parent_id` records which event belongs to the conditioning-context lineage.

These links may differ. For example, a delegated sub-agent can be caused by a main-agent call while using an isolated context. The reference never joins calls by text similarity or retokenizes prompt text.

`model_call` rows carry a role, `policy_id`, `policy_version`, immutable `model_id`, positive sampling temperature, behavior-logprob distribution identifier, exact nonnegative input and output token IDs, the SHA-256 of the input token-ID sequence, per-output-token behavior log-probabilities, and per-token provenance. V1 currently accepts only `neutral_temperature_scaled_policy`; a score from a different or unknown distribution cannot silently become a behavior-policy target. Only provenance `policy` is trainable. `environment`, `harness`, and `unknown` tokens remain masked, including assistant-role tokens inserted by a harness. A policy token must have a finite log-probability no greater than zero; all arrays must align token by token. The input hash detects accidental edits when the hash is left unchanged; it is a self-consistency check, not proof that the logger reconstructed the conditioning context from its declared parent or compaction event.

`evaluation` rows carry `evaluator_status` (`valid`, `pending`, or `invalid`), evaluator ID and configuration hash, evaluator version, `assessment_scope` (`partial`, `final`, or `intermediate`), an artifact or response fingerprint, score, branch, and whether the row is the designated execution outcome. Valid partial and intermediate assessments can be retained for audit, but only a valid `final` assessment can be designated as the training outcome. Pending or invalid records cannot carry a score. A valid zero is different from a missing score. V1 accepts scores only in `[0, 1]`, a VARE-local schema constraint that requires an explicit mapping before using another score scale. Hashes and evaluator identity are declarations; this reference does not verify them against artifact bytes or evaluator configuration bytes. In particular, the RVL bridge fills `artifact_sha256` with a canonical fingerprint of `{prompt_id, prompt, response}`. That fingerprint identifies the replayed tuple; it does not establish which bytes the verifier actually scored. Each execution may have at most one designated outcome; a group can materialize only when every declared execution is present and has a valid designated outcome.

The designated final score is an execution-level outcome and is applied to every policy token in that execution, including tokens on branches unrelated to the evaluation event's branch. This is the v1 contract; it is not branch-level credit assignment.

Event types accepted by schema v1 are `model_call`, `tool_call`, `tool_result`, `compaction`, `subagent_start`, `subagent_end`, `retry`, `timeout`, `cancelled`, `error`, and `evaluation`. Causal and context parent references must resolve within the execution and each relation must be acyclic.

## Materialization semantics

The reference requires `(group_id, execution_id, event_id)` to be unique and emits each unique `(group_id, execution_id, event_id, token_index)` once. Event and execution IDs may be reused in separate groups. Reusing the same event ID across multiple paths within one execution therefore does not duplicate it, but v1 does not detect equivalent content logged under different event IDs or discover shared prefixes by comparing requests. The producer must canonicalize a proxy request to one event ID. It emits one target per policy-origin output token and retains the event, branch, role, declared context hash, behavior log-probability, policy version, designated evaluator identity/configuration/version, declared artifact/response fingerprint, score, and final assessment scope.

For execution `i` with `L_i` policy tokens in a group of `N` declared executions, each emitted token receives weight `1 / (N * L_i)`. An execution with `L_i = 0` contributes zero but remains in the declared group denominator. Completeness means only that the observed number of executions matches the in-band `group_size`; there is no independent manifest of expected IDs and no check that the executions share task, policy, or reward protocol. `group_id` and `group_size` are caller assertions. This is a reference accounting convention, not a claim that every trainer uses the same objective or a complete GRPO implementation. The reference includes all policy tokens and does not implement QwenGyre's path selection, leaf caps, role priority, retry pruning, or overbranching rules.

Role priorities and path budgets remain harness-specific and are intentionally not hard-coded here. Causal and context parent links are validated as declared forests, but this does not establish that each model call's recorded input IDs are the actual context produced by its parent. The RVL bridge currently exercises only one turn per generation and does not provide QwenGyre-compatible tree/path selection or an end-to-end reproduction. It also does not compare RVL trainer loss, gradients, or updates against the reference.

## Reproduction

From the repository root, run:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=src python3.12 -m pytest -q \
  tests/test_trajectory_reference.py tests/test_rvl_integration.py \
  tests/test_rvl_trajectory.py
```

The tests cover a shared main-agent prefix, compaction, an isolated sub-agent context, a harness-inserted assistant token, timeout and separate partial/final assessments, a valid zero, missing/pending/invalid rewards, incomplete declared groups, empty ready groups, duplicate events, parent errors and cycles, token/log-probability alignment, provenance masks, stale context-hash detection, evaluator provenance fields, deterministic replay of the raw JSONL trace, and a 1,100-event parent chain. An SQLite replay fixture exercises RVL reader → RVL GRPO hook conversion → trajectory bridge, including two same-prompt groups with constant but different rewards, partial groups, prompt mixing, token/logprob mismatch, both pinned behavior-hash encodings, SQLite and post-read token/text mutations, duplicated group-ID mismatch, stale verifier versions, and legacy/malformed configuration hashes.

On 2026-10-14, the initial focused trajectory/RVL suite passed 43 tests and the full non-Math500 suite passed 444 tests. After adding the strict RVL bridge and boundary regressions, the focused suite passed 62 tests and the full non-Math500 suite passed 465 tests. The source-hash and lineage checks raised this to 69 focused tests and 472 full-suite tests. The final group-scoped event-ID and read-time reward-snapshot regressions bring the focused suite to 71 tests and the full non-Math500 suite to 474 tests. The raw trajectory fixture SHA-256 is `7569f9cefe1706025c92adeb9d03dae2f4027311ef5d877ee59093a25fe40fbd`. This M1 host's system `python3` is 3.9, so runs put the installed Python 3.12 directory first on `PATH`; pytest plugin autoload is disabled to avoid an unrelated global Hydra/ANTLR version mismatch.

## Evidence and limitations

This is E0 harness evidence on constructed CPU fixtures. It establishes that this reference accepts the declared control and rejects the enumerated mutations. The initial pre-fix RVL reader accepted missing, boolean, nonfinite, and out-of-range values as rewards (or raised inconsistently for `null`); regressions reject those cases in both summary and ready-experience paths. The RVL bridge regression also establishes that the tested reader preserves group IDs across a round trip through the existing GRPO hook, that same-prompt groups do not merge in the tested advantage calculation, and that known behavior hashes plus post-read generation digests reject token/text mutations. A read-time in-memory score snapshot catches later accidental score edits, but it does not authenticate scores already present in SQLite. This does not establish production frequency, a full logger's event coverage, continuity between parent events and model-call context tokens, content-level deduplication, independent verification of group membership, reward integrity on the normal pending-to-ready path, an immutable effective sampler configuration, evaluator/artifact authenticity, parity with RVL or TRL loss/gradients, model capability gain, GPU performance, or recursive self-improvement. QwenGyre's trajectory processing, branch policies, and weighted execution objective remain prior work; this bridge is a narrow local adapter/correctness result rather than a new RL method.

No model inference, optimizer update, GPU, or paid API was used. Trainer integration is a later gate and requires a concrete source path plus a separately frozen protocol; the reference passing its own tests is not sufficient authorization or evidence for that stage.
