# Verified trajectories to full-action GRPO

This bridge connects the existing durable long-horizon collector to the MLX
GRPO action-segment representation. It reuses the trajectory store, independent
grader, group validation, and optimizer path. It does not introduce another
collector or trainer, authorize a model-learning study, or establish task gain.

The implementation builds on the trace/enrollment bridge in
[#194](https://github.com/mitukx/VARE/pull/194), action segments in
[#204](https://github.com/mitukx/VARE/pull/204), and the lag-zero ratio check
proposed in [#195](https://github.com/mitukx/VARE/pull/195). These references
identify technical inputs; they do not imply that the referenced PRs merged.

## Data contract

[`EpisodeHarness`](../scripts/long_horizon_eval.py) enrolls a complete group of
episodes for one immutable Train task, policy, controller, and distinct member
seeds. The existing store records committed steps and the final trusted grade.
`grpo_samples_from_verified_group` audits that store and converts the group:

| Source | GRPO representation |
| --- | --- |
| One verified episode | One `Sample`, one terminal reward, one member index |
| Each generated tool-call or inference turn | One ordered `TrajectorySegment` |
| Exact tokens observed before that action | That segment's `prompt_ids` |
| Tokens generated by the policy | That segment's `completion_ids` |
| Sampling-time token probabilities | That segment's `behavior_logprobs` |
| Terminal/padding observations | No policy targets |

Only the initial prompt must agree across group members. Later contexts may
diverge after different actions and tool observations. Their recorded token
IDs are retained without decoding/re-encoding or concatenating observations
into a completion. The first segment also populates the legacy sample fields.

The group-relative terminal advantage is applied to every generated action
token. The step loss uses the existing mean over all trained action tokens;
prompt and tool-result tokens do not enter that denominator. This is terminal
reward credit across actions, without intermediate rewards or discounting.

## Sampling evidence

The collector records `vare_long_horizon_behavior_trace_v2` for every policy
turn. Each trace binds prompt/completion IDs and their counts, model output,
temperature, sampler distribution, and sampling log probabilities with hashes.
The samples carry `behavior_logprob_source="sampling_distribution"`, the
temperature/top-p settings, trajectory head, segment indices, and token counts.

The supported distribution is untruncated temperature softmax: temperature
must be positive, `top_p=1`, `top_k=0`, and `min_p=0`. In the pinned
[MLX-LM 0.32.2 sampler](https://github.com/ml-explore/mlx-lm/blob/93e6d4a6447b3080861985947f0820e76fcb957d/mlx_lm/sample_utils.py),
categorical sampling receives `logprobs * (1 / temperature)`.
[GenerationResponse](https://github.com/ml-explore/mlx-lm/blob/93e6d4a6447b3080861985947f0820e76fcb957d/mlx_lm/generate.py)
retains the corresponding pre-temperature vector and emitted token, including
the final EOS token. The collector scales that vector with the same arithmetic,
normalizes in float32, and records the selected token's log probability.
No model forward or current-checkpoint rescore replaces this observation.

The converter requires every generated action's v2 trace and sampling scores.
Historical first-action-only records, missing later traces, unsupported
samplers, nonfinite scores, mismatched hashes/counts, or policy changes reject
the entire group. A zero-token generated turn is also rejected; it is not
silently removed from an otherwise trainable episode.

Omitting an action also requires a collector-consistent state transition.
Padding must preserve an already-stopped state exactly; a terminal observation
may only add an allowed budget stop reason without changing tokens or files.
Generated actions cannot resume after either kind of stop. Each action's token
counter increment must equal its recorded completion length. Relabeling a
generated step as an observation therefore cannot hide its targets.

## Reward and provenance boundary

Conversion requires complete verified membership, identical immutable task and
initial-source provenance, a registered verifier/configuration, and a bound
controller. Every step must retain the enrolled policy identity. The raw final
grade must bind to the task, source revision, patch, trajectory head, and final
candidate bytes. Broken provenance is rejected rather than assigned reward zero.

The terminal reward remains the existing independently graded `final_success`,
including required public-test success. Legitimate failed episodes remain in
the comparison group. A successful finish command or an earlier passing test
does not replace the final outcome. Non-Train or synthetic records are refused;
diagnostic fixtures do not qualify real tasks or become held-out evidence.

The boundary assumes a trusted collector, task manifest, and verifier registry.
Hashes and consistent metadata detect corruption under that ownership contract;
they do not authenticate records supplied by an arbitrary database writer.
Successful conversion is a structural check, not permission to train on a cohort.

## Update boundary

[`grpo_mlx.py`](../src/vare/grpo_mlx.py) preserves already recorded behavior
scores. `compute_behavior_logprobs` can fill missing legacy scores only; its
caller must own the exact behavior checkpoint. Missing recorded collector
scores are an error, and staged legacy fills are published only after scoring
finishes. Collector temperature must match the loss configuration.

Collector samples retain `behavior_group_size`. At use time, group validation
again requires a common collector origin, the complete expected membership,
and exactly the enrolled member indices, even when `cfg.group_size` is unset.
Slicing a converted group therefore cannot silently change its advantage set.

Before applying an optimizer update, the trainer validates current checkpoint
identity and policy lag, then checks each action segment's differentiated
current-policy scores. A lag-zero segment requires maximum absolute log ratio
at most `1e-6`; invalid ratios, loss diagnostics, or gradients reject the update.
Recorded denominators are never overwritten to force a ratio of one.

Backend numerical differences may make real sampling and differentiated scores
fail this strict check. Such a mismatch stops the update and needs a separate
measurement; this bridge neither relaxes the tolerance nor proves agreement
for a pretrained model, reduced precision, or an accelerator.


retains the JUnit result plus resolved environment as run artifacts. The job
uses offline model access and newly generated synthetic fixtures; no pretrained
weights or task dataset are downloaded.

### Read-only sampling-to-gradient alignment preflight

The trainer rejects a lag-zero update if any generated action has a sampled
versus differentiated log-probability difference above `1e-6`. Before a
pretrained model update, run the following **read-only numerical audit** on
an existing complete, verified Train group and the exact behavior checkpoint.
It checks three discrepancies separately: sampling versus ordinary forward,
sampling versus differentiated forward, and ordinary versus differentiated
forward. No optimizer, task grading, checkpoint update or held-out access is
performed. It refuses legacy recomputed scores, incomplete groups, stale
policy labels, unsupported samplers and oversized diagnostics.

```python
from vare.grpo_mlx import GRPOConfig, audit_on_policy_sampling_alignment
from scripts.long_horizon_eval import grpo_samples_from_verified_group

# Load the exact behavior checkpoint/model and its registered trusted store
# separately; keep the runtime mode identical to the intended update.
# The caller is responsible for binding checkpoint bytes, not merely an ID.
samples = grpo_samples_from_verified_group(store, group_id)
report = audit_on_policy_sampling_alignment(
    model, samples, GRPOConfig(group_size=len(samples), temperature=0.7),
    policy_checkpoint_id=checkpoint_id, policy_step=checkpoint_step,
    max_action_segments=32, max_completion_tokens=2048,
)
print(report)
```

The example intentionally leaves `store`, `model`, `group_id`,
`checkpoint_id` and `checkpoint_step` to the caller; it is **not** a
command that downloads a model or authorizes any new rollout. The report
contains counts, conservative nearest-rank p50/p95/max absolute differences,
and the would-reject decision, but no task contents or raw token sequences.
A clean report on a seeded toy model does not establish agreement for a
pretrained model or a reduced-precision/Metal backend. A rejected real-model
report must be retained as evidence and investigated; do not loosen the
trainer guard or overwrite the recorded denominators to make it pass.


### Pinned defect replay

[`reproduce_grpo_trajectory_guards.py`](../scripts/reproduce_grpo_trajectory_guards.py)
checks two defects against the exact trainer source at
[`2876218`](https://github.com/mitukx/VARE/commit/287621875c08c22419810e021f9180f0d830b259).
It verifies that source's SHA-256 before importing it. The fixture is a seeded
64-token bigram table, two forced-action episodes with two actions each, and
terminal rewards `[1, 0]`. One later-action denominator is perturbed by `-0.5`
log-probability units. This is an injected numerical defect, not model output
or independently measured task success.

The retained [raw result](../results/grpo-trajectory-bridge-v1/guard-replay.json)
records source/reproducer hashes and the Linux x86-64, Python 3.12.14, MLX 0.32.2
CPU environment:

| Check | Pinned baseline | Patched trainer |
| --- | --- | --- |
| Calling the behavior-score helper again | Overwrites recorded scores | Preserves recorded scores |
| Updating with the inconsistent later-action score | Applies an update | Rejects at the lag-zero guard |
| Parameters after that attempted update | Changed | Unchanged |
| Optimizer step after that attempted update | 1 | 0 |

Reproduce from a checkout containing the baseline commit:

```bash
git fetch --no-tags --depth=1 origin 287621875c08c22419810e021f9180f0d830b259
PYTHONPATH=src python scripts/reproduce_grpo_trajectory_guards.py
```

The CI job also runs this replay and retains its JSON. The replay does not
overwrite committed evidence or access earlier task data.

### Local validation

The combined focused suite completed on Linux x86-64 with Python 3.12.14 and
MLX/MLX CPU/MLX-LM 0.32.2: **171 passed, zero skipped** (102 collector/converter
tests and 69 trainer tests; 17.39 seconds for the combined run). This includes
the production converter-to-gradient-to-Adam path with a forced-action 4-by-1024
float32 table model, an independent gradient calculation, later-action weight
updates, checkpoint restoration, and identical continuation after restoration.
The seeded table is synthetic and is not a pretrained coding policy.

Ruff 0.15.12 passed for `src`, `tests`, the collector, and the replay script.
Mypy 1.19.1 passed for all 99 `src/vare` source files in a clean environment
matching the existing typecheck job. That job intentionally has no optional
MLX/NumPy runtime: the repository targets Python 3.11 typing, while the NumPy
2.5.4 stubs in the numerical environment use Python 3.12-only syntax.
The workflow parsed successfully and `git diff --check` passed.

These checks do not run a protected cohort or a pretrained-model learning
comparison. Frozen protocols, prior results, and readiness decisions remain
unchanged. Report executed tests, backend, skips, and limits separately from
the implemented contract.
